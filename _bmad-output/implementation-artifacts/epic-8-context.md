# Epic 8 Context: India Compliance — GST & E-way

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Every dispatch produces a GST-compliant invoice without manual work, and consignments above the e-way threshold generate e-way bills (single or batch) so filing a period closes without touching the GST portal by hand. Invoices reconcile exactly to what actually shipped — line values are dispatched qty × rate × GST computation, computed in the system's exact-arithmetic conventions, never floats. Compliance generation rides the same delivery discipline as labels: a generation failure is retryable and never blocks recording the dispatch.

## Stories

- Story 8.1: GST-compliant invoicing
- Story 8.2: E-way bills and HSN summary

## Requirements & Constraints

- Invoice line values reconcile exactly to dispatched qty × rate × GST computation (FR-26). GST rates and HSN codes come from catalog data; place-of-supply rules apply from the dispatch's origin/destination context.
- Money math is integer paise; GST rates are basis points; quantities are milli-unit scaled integers (AD-9). Decimal conversion happens only at presentation edges — the computed invoice is exact arithmetic end to end.
- E-way bills generate for consignments above the (versioned-config) threshold, single and batch; thresholds are never code literals (AD-9).
- Generation failure is retryable and NEVER blocks recording the Dispatch (FR-26/AD-7) — dispatch state lands first, compliance artifacts follow through retries.
- The HSN summary produces per accounting-period totals for filing (SM-8 target: ≥ 90% of eligible dispatches system-generated by month 3).
- Compliance artifacts (invoices, e-way payloads/receipts) are tenant-scoped records with the same retention and scoping discipline as the rest of the system — the port exists in the spine, but its STORAGE is this epic's to own.

## Technical Decisions

- **New `compliance/` module owning FR-26.** *(Amended by 8-1: `src/modules/compliance/` was already taken by 12-5's temperature-excursion module, so the GST module is the sibling `src/modules/invoicing/`. 8-2's e-way and HSN work extends `invoicing/`.)* GST invoices, e-way generation, and the HSN summary live there; it reads through facades (outbound dispatch/order state, catalog SKU data) like every other module — never tables across module lines.
- **One `EwayGateway` port** for the e-way transport path (PRD OQ3: official portal API vs GSP intermediary — decide which before building 8-2; the port makes the choice swappable without touching the spine). No outbound integration call may leave the metered adapter ports (AD-17/AD-6).
- **Transactional outbox for generation (AD-7).** Dispatch commits state changes and the outbound compliance event in one transaction; the relay publishes at-least-once; external failures (portal error, GSP down) retry with backoff and dead-letter — the dispatch is never retried or rolled back.
- **Credentials follow the AD-15 pattern.** GSP/GST portal credentials are as sensitive as channel tokens (a GSP credential grants filing-adjacent capability); envelope-sealed storage referencing by id, never env vars or code, never on any wire shape — the channels/carriers vault pattern is the precedent.
- **GST/e-way-adjacent records are India-region-resident** (spine assumption ap-south-1, release-gating for compliance storage — the compliance module's storage is the thing that moves if residency is ever resolved otherwise).
- **Regulatory constants are versioned config data** (thresholds, rates): a tracked regulatory-watch source, not hardcoded constants; changes are versioned rows, never edits in place.

## UX & Interaction Patterns

- The web sidebar gains a **Compliance** surface: invoices listed per dispatch with document access (8-1), e-way generation/batch actions and the per-period HSN summary for filing (8-2). Same panel conventions as the other surfaces — problem-details refusals rendered inline, cursor-paginated lists.

## Cross-Story Dependencies

- **Epic 8 ← outbound (Epic 4).** Invoices/e-way keys off the dispatch state machine's shipped/packed state and its dispatch records; the writeback and label machinery are the precedent for eventing.
- **Epic 8 ← catalog (Epics 2/11).** GST rate, HSN code, and SKU description data come from catalog: whether they are additive fields on the catalog's SKU/variant tables or compliance-owned config rows keyed by SKU is an 8-1 design question the spec must settle (variant/kits from Epic 11 must compose — kit dispatches invoice per component).
- **Place of supply** needs the warehouse's origin context (state) and the consignment destination address (Epic 11's shipment-address model) — both must exist before invoicing rules can evaluate.
- **Within the epic:** 8.1 (invoice model, GST arithmetic, document storage, Compliance surface) precedes 8.2 (e-way gateway port, batch generation, HSN summary) — e-way receipts reference the invoice.
- **Epic 21-5 (client invoices) later extends this epic's invoice model** for 3PL billing clients — keep the invoice core client-agnostic.
- Epic 13/14 (reporting/analytics) consume the compliance artifacts' audit-trail linkage later.
