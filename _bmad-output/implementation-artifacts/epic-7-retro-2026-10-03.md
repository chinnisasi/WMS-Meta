**Fix-now candidates (proposed to the human, not applied):**

- **D1 (HIGH — verified twice): the variant lookup calls a Shopify endpoint that does not exist.** `channel-shopify-port.ts:121` resolves `skuId` → `inventory_item_id` via `GET {base}/variants.json?sku=…`; Shopify's REST Admin API has **no top-level `/variants.json` and no `sku` query param** (only `products/{id}/variants.json` with `fields/limit/presentment_currencies/since_id`; verified against shopify.dev's Product Variant resource, which also flags the REST resource deprecated since API 2024-04 — new integrations belong on GraphQL). The transport tests mock the fabricated URL (`channel-transports.spec.ts:167`), so the suite is green against a 404-per-call reality. Effect on the real transport: cache-first publish works, but the FIRST publish of any un-cached scope 404s → the cache never fills → availability sync dead-letters every uncached scope; RD-6's resolve-at-publish never resolves. The 2 h run could not see this: it rode the test provider (`admitTestProviderInDb`, `testAvailabilityArm`). Fix shape: GraphQL `productVariants(query: "sku:…")` fallback (REST is deprecated — go GraphQL directly), refuse ambiguous multi-variant refs as `item-unresolved`, and pin the resolved-item read against the REAL API's response shape.
- **D2 (HIGH — verified): the outbox drain serializes behind writeback HTTPS.** `outbox.ts:172-186` delivers rows one at a time (`for (const row of rows) { await this.deliver(row) }`), and `event-bus.ts:53-56` awaits every handler sequentially; the writeback handler performs per-delivery HTTPS up to the channel timeout. One slow/unreachable channel stall blocks the whole relay cycle in timeout quanta — healthy connections' availability-sync deliveries (all tenants) queue behind one bad writeback. The 2 h run measured writeback lag against the **test adapter** (no real HTTPS stall), so the load evidence does not cover this. Fix shape: shorter per-arm writeback timeout, bounded-concurrent dispatch, or a dedicated drain plane — a design question, not a patch.
- **D3 (HIGH — verified): the sync worker's stall/skip/SQL paths run against nothing.** The worker test (`channel-sync.spec.ts:676-719`) stubs `execute` with canned rows and the facade completely; `test/architecture.spec.ts` gates workers off; so the enumeration SQL (`integrations … order by … limit`, `jobs.module.ts:728-736`), `recordSyncStall` (:760), and the breaker WHERE never execute in any suite against a real DB. A SQL typo in the enumeration kills every production sync tick with the suite green (dies silently in the outer catch). Fix shape: one real-DB worker-tick suite (the replenishment tick's pattern) with a facade that throws.
- **D4 (MEDIUM — verified, and a documentation-defect finding): disconnect revokes the stale Phase-1 blob across the rotate race — and PENDING.md's "settled" row misdescribes the code.** The code's own comment (`channels.command.ts:936-940`: "this attempt uses ITS blob") confirms `openCredential(existing.credentialSealed!)` uses the Phase-1 read (row taken at `:840`), while the Phase-2 re-lock selects `CONNECTION_COLUMNS` (`channels.view.ts:85` — no `credentialSealed` column). A rotate committing between Phase 1 and the delete leaves the row deleted with a **live, never-revoked rotated credential** at the channel. `docs/design/PENDING.md:134`'s struck-through "settled by 7-2 (RN-7)" entry claims the revoke "re-reads the credential at the re-lock" — it does not; the settle triage verified a claim, not the code (this retro's own lesson in miniature). Fix shape: extend the Phase-2 lock read with the sealed blob and revoke that; retract/correct the PENDING row; add the module-doc gotcha.
- **D5 (MEDIUM): divergent mapping-write normalization.** Seed arm stores `item.externalRef` untrimmed (`channels.publish.ts:682-740`); the mappings PUT trims and dedupes trimmed (`channels.command.ts:1124-1145, 1209`); ingest exact-matches against whichever writer ran (`channels.ingest.command.ts:123-129`). A seeded `" SKU-1"` makes every webhook order of that SKU `unmapped` while the FE editor shows a correct mapping. Fix shape: one shared normalization/validation function both writers + ingest call.
- **D6 (MEDIUM regression gap): the breaker's half-open → success → closed transition is untested** — every breaker-motion test walks failure directions only (`channel-sync.spec.ts:492, 614`; the success-drain test :638 starts from closed). A regressed `closed` write leaves a recovered connection half-open forever with the suite green.
- **D7 (MEDIUM): sync worker's connection cap starves the tail past 200** — static `order by tenant_id, created_at, id` + head-only limit (`jobs.module.ts:726-738`) means connection 201+ never ticks while ≥200 stay connected; the cap claim ("delays rather than starves") holds only for the *cycle* shape, not across cycles, and the skip predates any stamp/meter so nothing flags it.

**Defer/tracking rows (each verified-or-anchored at code level by the lens pass, reference-only here):**
