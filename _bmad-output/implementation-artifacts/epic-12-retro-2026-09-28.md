### High

- **H1 — An excursion on a cage-class bin leaves zero compliance trace.** The sweep's `holdScopeInTx` asserts `secure.move` mid-transaction, *after* the excursion row and its zero-delta ledger events would write; the 403 rolls back the whole tx. The most sensitive stock — the one a temperature excursion is most likely to hit, and the one case where a recorded-but-unquarantinable observation matters most — produces no excursion row, no ledger event, no queue item; the device arm then classifies the replayed op as rejected/dropped with a summary line only (L5 compounds it). Observed excursion, no record. [ADV; `excursion.command.ts` hold path, `replay-classification.ts:76-100`] → fix candidate: record the excursion + a refused-hold marker before the hold core runs, or a compensating audit row.

### Process lessons (fold into IMPLEMENTATION-GUIDE via a8)

1. **Id-vocabulary claims are verified against the lib, not asserted** — 12-7's spec said "ULID" where the code checks UUIDv7; it survived design review and all three code lenses, and the same error class recurred inside a code comment in 12-8 (`use-cold-chain.ts`, L10). A vocabulary claim in a spec gets a one-line mechanical check against the actual validator before freezing.
2. **An acceptance criterion names its verification instrument.** T8 froze "a screen-level flow …" with no screen-test convention to satisfy it (M7); the disposition ("recorded as satisfied at the engine level") silently narrowed a declared clause. Spec the instrument with the criterion or reword the criterion.
3. **A cross-repo mirror without a mechanical check is a comment, not a guard** (M6): parity pins that import their own copy prove nothing. The FE↔BE drift guard exists; the BE↔mobile seam has none.
