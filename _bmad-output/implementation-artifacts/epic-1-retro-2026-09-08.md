### Architecture delta (BE, delegated lens)

- **A-1 — Catalog → tenancy internals without facade exports** (defect-class architecture drift, 1.4 `b73075a`): catalog imports `hashCommandPayload` (tenancy/idempotency-guard), `idempotencyKeyReuse` (tenancy/registration.command!), `assertPermission` (tenancy/permissions) directly (`import.command.ts:19-25`, `sku.command.ts:11-17`) — only `TenancyService` is in TenancyModule's `exports` (`tenancy.module.ts:44`); the rest are module-internal files crossing the boundary. The spine convention says "communicate only through interfaces and domain events".
- **A-2 — First two-way module cycle, tenancy ↔ catalog** (accepted drift, documented): `forwardRef(() => TenancyModule)` in `catalog.module.ts:3,20` and `forwardRef(() => CatalogModule)` in `tenancy.module.ts:3,16`. Direction 1 (1.4): checklist reads catalog summary via `CatalogFacade` (`tenancy.service.ts:10`, facade `catalog.facade.ts:23-68`). Direction 2 (1.5): catalog commands read role via `TenancyService.getMemberRole` inside their own transactions (`sku.command.ts:159-166`, `import.command.ts:25`). Each direction was justified in-story; no single session saw the cycle forming both ways.
- **A-3 — `idempotencyKeyReuse()` stranded in a story-specific file** (duplication enabling drift): defined in `registration.command.ts:153` (1.2), imported by 4 later command files and 2 catalog files. A generic factory living in one story's file.
- **A-4 — Zones/bins never got a module** (accepted, but compounds A-5): 1.3 (`64b727e`) added `zone.command.ts`/`bin.command.ts` inside tenancy; `tenancy.service.ts` grew +222 in that commit alone and is now the only service file touched by every story 1.2→1.5 (+130/+222/+24/+75).
- **A-5 — Replay-suppression divergence across stories** (cross-story divergence with a real future consequence): 1.2–1.4 commands thread a `{snapshot, replayed}` flag and gate event publishing with `if (!replayed)` (`warehouse.command.ts:142-146`, `zone.command.ts:148-152`, `bin.command.ts`, `sku.command.ts:251/266`, `import.command.ts:355/359`); 1.5's `users.command.ts` publishes unconditionally on all three commands (lines 236, 365, 486 — zero `replayed` hits). On idempotent replay, `user.invited`/`user.role_changed` re-publishes. Harmless only because the bus is `LoggingEventBus` — with the outbox relay (epic 2's seam, `outbox.seam.ts` contract-only), replayed re-publishes would double-write.
- **A-6 — Mobile app is outside the generated-client discipline** (FE lens): `mobile/src/api.ts:8-22` hand-writes `HealthResponse` and calls the BE with raw `fetch` (1.1 `80bf90e`, untouched after) — AD-8 says *no hand-written API types on the consuming side*; the CI drift guard covers only web.
