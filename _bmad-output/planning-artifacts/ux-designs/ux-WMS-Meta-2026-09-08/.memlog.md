- (direction) Fast path, sources = PRD + addendum + architecture spine + SPEC-WMS-Meta (all four confirmed). Journeys mirror PRD UJ-1..4 verbatim (Priya ops head, Ramesh floor operator, Ankit founder). Stakes: consumer-grade launch product for paying B2B tenants — not internal tooling.
- (decision) [ASSUMPTION] Brand: product name is the PRD working title 'WMS'; no brand deck exists. Visual posture = industrial clarity — a floor tool that respects speed and correctness, not a consumer app. India-first context (₹, dd/mm, IST display) assumed.
- (decision) Form factor (settled by PRD/spec): two surfaces — responsive web dashboard for Owner/Ops Manager/Accountant (Next.js 16) and native mobile scan client for Operators (Expo/RN 0.86, offline-first, AD-4). No tablet/desktop-native surface in v1.
- (decision) Web UI system: shadcn/ui on Next.js + Tailwind (going choice for the stack). DESIGN.md specifies brand-layer delta only; shadcn defaults are the contract for unlisted tokens. Mobile inherits platform conventions (iOS HIG / Android Material) with a shared token layer for brand colors.
- (decision) Scan feedback color discipline (floor client, load-bearing): full-screen color-coded result banner after every scan — green = accepted, red = rejected with reason, amber = attention (FEFO override prompt, QC hold). Scan result is the loudest element on any mobile task screen; ≥48dp targets, glove/one-handed friendly.
- (decision) IA web (10 areas): Overview (KPIs FR-27), Inventory (stock by bin/SKU, batch/serial, ledger viewer), Inbound (POs, GRNs, QC), Outbound (orders, waves, picklists, pack/dispatch), Moves (transfers, adjustments, counts), Replenishment (reorder, expiry), Channels (connections, buffers, sync health), Compliance (invoices, e-way), Reports/Audit, Settings (warehouse/bins, catalog, users/roles, import).
- (decision) IA mobile: badge-in → Task inbox (tabs: All / Pick / Putaway / Count / Transfer; picklists, putaways, counts per FR-29) → one linear flow per task type. Scanning is a global primitive (camera scan overlay + HID), never a screen. Queue depth indicator while offline (FR-14) is a persistent header element, not an error state.
- (decision) [ASSUMPTION] Dark mode: web light-only in v1; mobile follows system setting (dark aids night-shift floors, battery). i18n: English UI v1, ₹ INR, dd/mm/yyyy, IST display; Hindi/vernacular is a v2 candidate (concern named, not decided).
- (decision) Accessibility floor: WCAG 2.2 AA on web; mobile dynamic type honored, screen-reader labels on all task states, Reduce Motion respected; scan targets ≥48dp. Contrast verified for the scan-result color pairs against AA at large text.
- (decision) Web interaction posture: mouse/keyboard data tool (⌘K command palette, dense tables, cursor pagination, no infinite scroll), hover reveals row actions on desktop only. Mobile posture: scan-first — every task flow is scan → feedback → next; typing is the fallback, not the default.
- (decision) Anti-patterns (rejected): gamification/streaks on pick rates (surveillance posture, contradicts SM-C1 'do not minimize rejections'); celebratory animations; hover-only affordances (touch phones on floor); badge-count notification spam; kanban boards as default order view; infinite scroll on data tables (cursor pagination only, audit export is async).
- (assumption) Voice: plain, terse, operator-respecting. Numbers over adjectives ('3 POs awaiting receipt', not 'Great news!'). Errors state what happened + what to do ('Bin A-03-12 is blocked — pick from B-01-04 instead'). No exclamation marks in system copy.
