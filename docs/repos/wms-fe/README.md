## Stack & structure (Story 1.2)

- Next.js 16.3 App Router (React 19, Tailwind 4, TypeScript 6, bun as package manager). Dev server runs on **:3001** (`bun run dev`) so the backend keeps :3000.
- Design-token layer in `src/app/globals.css` mirrors DESIGN.md (`_bmad-output/planning-artifacts/ux-designs/ux-WMS-Meta-2026-09-08/`): brand delta `#1E4E8C` / `#16794C` / `#B45309` with dark-mode foreground pairs, 4/6/8px radius scale, 28px semibold tabular-nums `kpi` style. Pinned by `src/lib/brand-tokens.test.ts`.
- **Route groups:** `src/app/(app)/` holds the 12 in-shell surfaces (Overview … Settings — everything rendering `AppShell`); `src/app/(auth)/` holds `/register` and `/login` outside the shell (signup must not render the app sidebar). The root layout is document chrome only.
- **Auth flow (Story 1.2):** `/register` posts tenant registration with a fresh ULID `Idempotency-Key` per submit, then routes to `/login?email=…` (registration mints no token). `/login` calls sign-in and stores the session in localStorage (`wms-session` key, contract in `src/lib/auth.ts`: token + tenant + expiry) — an expired token reads as signed-out. **`readSession()` is a pure snapshot getter** — it never mutates storage or dispatches events (it feeds `useSyncExternalStore` during render); the **expiry watchdog** (review loop 3) is what makes the TTL visible: `writeSession` schedules a timer that dispatches `SESSION_CHANGED_EVENT` at `expiresAt` (rescheduled on rewrite, cleared on clear), flipping every subscribed surface to signed-out the moment the token dies — submit handlers' `session === null` guard can no longer silent-no-op. **Backend-401 authority (review loop 3):** `src/lib/api/client.ts` runs a response interceptor that calls `clearSession()` on any 401 — a rejected token is dropped immediately (the request interceptor also calls `ensureSessionHint()` to re-assert the hint cookie after a browser-side clear while the session is still valid). **Auth gate (review loop 2):** `src/proxy.ts` (Next 16's `proxy` convention — `middleware.ts` is deprecated in this version; the decision lives in the pure `gate(pathname, hasHint)` function, tested in `src/proxy.test.ts`) redirects signed-out visitors of app surfaces to `/login` and signed-in users away from the auth pages. It reads a **presence-only hint cookie** (`wms-session-hint`, set/deleted by `writeSession`/`clearSession`, TTL matched to the token, `Secure` on https, **written only when the localStorage write succeeded**, no token material) because localStorage is invisible server-side; it is a UX gate, not an enforcement boundary — the backend rejects unauthenticated calls regardless. **Sign-out:** `SignOutButton` (`src/components/auth/sign-out.tsx`) renders in the sidebar footer and the mobile header menu, calls `clearSession()` and routes to `/login` — hidden entirely when signed out. Errors branch on the problem-details `code` (`duplicate-email`, `unauthenticated`, `idempotency-key-reuse`), never on prose. The Settings page hosts warehouse creation (fresh ULID key per submit; duplicates surface `duplicate-warehouse-code` naming the code). Warehouse listings everywhere share one loader — `useTenantWarehouses()` (`src/lib/use-tenant-warehouses.ts`): session-**identity**-scoped fetch, full cursor chain (the walk lives in `src/lib/fetch-all-warehouses.ts`, bounded 20 hops, unit-tested), stale cross-tenant pages filtered at render. Consumers: the sidebar switcher, the **mobile header menu** switcher (`src/components/shell/warehouse-switcher.tsx`, `className` decides visibility per mount — review loop 2 made mobile a first-class mount; Esc/outside-click close the disclosure and `onPicked` lets the mobile mount close the header menu), and the Settings list. The picked warehouse is a localStorage convenience (`src/lib/warehouses.ts`) keyed **per tenant** (`wms-active-warehouse:<tenantId>`) — the backend has no active-warehouse concept until Epic 2. localStorage-derived UI state goes through `useSyncExternalStore` subscriptions (`subscribeSession`, `subscribeActiveWarehouse`) — never synchronous setState in effects.
- Sidebar IA skeleton: 12 surfaces (Overview, Inventory, Inbound, Outbound, Moves, Conflicts & Reviews, Notifications, Replenishment, Channels, Compliance, Reports / Audit, Settings) — placeholder routes except the tenancy features above; interaction primitives (⌘K palette: Esc closes, Enter commits; single modal layer) in `src/components/shell/`; cursor-pagination data-table primitive in `src/components/data-table/`.
- **Zones/bins setup + checklist (Story 1.3):** `Settings` hosts the setup checklist card (`src/components/settings/setup-checklist-card.tsx` — "N of M done" badge, progress bar, tick rows + Continue links per the overview mockup; data from `useSetupChecklist()`, `src/lib/use-setup-checklist.ts`, refetched on warehouse/zone-bin change events) and the zones/bins setup group (`src/components/settings/zone-bin-setup.tsx` — zone create, grid generator, manual bin, and the zone→bins `DataTable` with the block toggle; the warehouse being configured follows the switcher's per-tenant localStorage pick, falling back to the first warehouse). Loaders mirror `useTenantWarehouses`: `useWarehouseZones` walks the full cursor chain through the generic walker `fetchAllPages` (`src/lib/fetch-all-pages.ts`, unit-tested), `useZoneBins` serves one cursor page wired to the DataTable's Prev/Next. Zone/bin mutations broadcast `ZONES_CHANGED_EVENT` (`src/lib/zones.ts`) so the checklist and lists refetch; `rejectionReason` in the setup component branches on `duplicate-zone-code` / `duplicate-bin-code` / `grid-too-large`, never on prose.
- **Mobile lives in this repo for now**: `mobile/` is a self-contained Expo 57 app (own package.json/tsconfig/app.json, zero imports from the web app) so extraction to its own repo is mechanical. Story 1.1 human decision — do not register a wms-mobile repo yet.

## Interface Contract (what this repo depends on from `wms-be`)

Keep this current whenever a cross-repo change lands — this is what lets an agent catch "this backend change breaks the frontend" *before* making the change, not after.

- Backend base URL / API version consumed: `NEXT_PUBLIC_API_BASE_URL` (default `http://localhost:3000/api/v1`), api document version 1.0.0
- Endpoints called (Story 1.1 + 1.2 + 1.3 scope): `GET /api/v1/health` (Overview page health check, live per request); `POST /api/v1/tenants` + `POST /api/v1/tenants/sign-in` (auth pages); `POST /api/v1/tenants/{tenantId}/warehouses` (Settings) + `GET /api/v1/tenants/{tenantId}/warehouses` (sidebar switcher) — the warehouse pair requires `Authorization: Bearer <token>` from sign-in and an `Idempotency-Key` on the create. Story 1.3 adds the zones/bins setup surface (all under `Settings`): `POST/GET .../warehouses/{warehouseId}/zones`, `GET/POST .../zones/{zoneId}/bins`, `POST .../zones/{zoneId}/bins/grid`, `PATCH .../warehouses/{warehouseId}/bins/{binId}` (block toggle) — every mutating call carries a fresh ULID `Idempotency-Key` per submit — and `GET /api/v1/tenants/{tenantId}/setup-checklist` (computed on read; catalog/users steps are honestly pending until stories 1.4/1.5). See `docs/repos/wms-be/README.md` for the full request/response/error contract.
- Shared types/DTOs: **generated, never hand-written** — `src/lib/api/generated/` via `@hey-api/openapi-ts` 0.99.0 (pinned). Pipeline: after any wms-be contract change run `bun run openapi:export` in wms-be, then `bun run api:generate` here, then commit the regenerated client. The generated client reads the spec from `../../backend/wms-be/openapi/openapi.json` (workspace-relative). Both CI pipelines guard this: wms-be fails if the committed spec doesn't match the code; wms-fe fails if the committed client doesn't match the spec.
  - **Mobile exception (temporary):** `mobile/src/api.ts` hand-writes `HealthResponse` until `mobile/` is extracted to its own repo with its own codegen (tracked in `_bmad-output/implementation-artifacts/deferred-work.md`). Until then, treat a wms-be `HealthResponse` change as also breaking mobile.
  - **Import convention:** import SDK functions via `src/lib/api/client.ts` — it applies the base-URL config to the shared generated client **and** attaches the stored bearer token from `readSession()` via a request interceptor. Importing the generated barrel (`@/lib/api/generated`) directly skips that config and calls whatever origin the bundle was served from, unauthenticated.
- Auth mechanism expected from the backend: 15-minute HS256 JWT from `POST /tenants/sign-in` (`{accessToken, tokenType: 'Bearer', expiresInSeconds, tenant}`), stored in localStorage, attached by the interceptor; **no refresh token** — when it expires the app reads as signed-out and the user signs in again.
- Env vars this repo needs pointed at `wms-be`: `NEXT_PUBLIC_API_BASE_URL` (web; see `.env.example`) and `EXPO_PUBLIC_API_BASE_URL` (mobile; same default). Both are **inlined at build time** by Next.js/Expo — setting them at deploy runtime does nothing; retargeting the backend requires a rebuild.
