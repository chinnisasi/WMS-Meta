## Stack & structure (Story 1.2)

- Next.js 16.3 App Router (React 19, Tailwind 4, TypeScript 6, bun as package manager). Dev server runs on **:3001** (`bun run dev`) so the backend keeps :3000.
- Design-token layer in `src/app/globals.css` mirrors DESIGN.md (`_bmad-output/planning-artifacts/ux-designs/ux-WMS-Meta-2026-09-08/`): brand delta `#1E4E8C` / `#16794C` / `#B45309` with dark-mode foreground pairs, 4/6/8px radius scale, 28px semibold tabular-nums `kpi` style. Pinned by `src/lib/brand-tokens.test.ts`.
- **Route groups:** `src/app/(app)/` holds the 12 in-shell surfaces (Overview … Settings — everything rendering `AppShell`); `src/app/(auth)/` holds `/register` and `/login` outside the shell (signup must not render the app sidebar). The root layout is document chrome only.
- **Auth flow (Story 1.2):** `/register` posts tenant registration with a fresh ULID `Idempotency-Key` per submit, then routes to `/login?email=…` (registration mints no token). `/login` calls sign-in and stores the session in localStorage (`wms-session` key, contract in `src/lib/auth.ts`: token + tenant + expiry) — an expired token reads as signed-out. **`readSession()` is a pure snapshot getter** — it never mutates storage or dispatches events (it feeds `useSyncExternalStore` during render); the **expiry watchdog** (review loop 3) is what makes the TTL visible: `writeSession` schedules a timer that dispatches `SESSION_CHANGED_EVENT` at `expiresAt` (rescheduled on rewrite, cleared on clear), flipping every subscribed surface to signed-out the moment the token dies — submit handlers' `session === null` guard can no longer silent-no-op. **Backend-401 authority (review loop 3):** `src/lib/api/client.ts` runs a response interceptor that calls `clearSession()` on any 401 — a rejected token is dropped immediately (the request interceptor also calls `ensureSessionHint()` to re-assert the hint cookie after a browser-side clear while the session is still valid). **Auth gate (review loop 2):** `src/proxy.ts` (Next 16's `proxy` convention — `middleware.ts` is deprecated in this version; the decision lives in the pure `gate(pathname, hasHint)` function, tested in `src/proxy.test.ts`) redirects signed-out visitors of app surfaces to `/login` and signed-in users away from the auth pages. It reads a **presence-only hint cookie** (`wms-session-hint`, set/deleted by `writeSession`/`clearSession`, TTL matched to the token, `Secure` on https, **written only when the localStorage write succeeded**, no token material) because localStorage is invisible server-side; it is a UX gate, not an enforcement boundary — the backend rejects unauthenticated calls regardless. **Sign-out:** `SignOutButton` (`src/components/auth/sign-out.tsx`) renders in the sidebar footer and the mobile header menu, calls `clearSession()` and routes to `/login` — hidden entirely when signed out. Errors branch on the problem-details `code` (`duplicate-email`, `unauthenticated`, `idempotency-key-reuse`), never on prose. The Settings page hosts warehouse creation (fresh ULID key per submit; duplicates surface `duplicate-warehouse-code` naming the code). Warehouse listings everywhere share one loader — `useTenantWarehouses()` (`src/lib/use-tenant-warehouses.ts`): session-**identity**-scoped fetch, full cursor chain (the walk lives in `src/lib/fetch-all-warehouses.ts`, bounded 20 hops, unit-tested), stale cross-tenant pages filtered at render. Consumers: the sidebar switcher, the **mobile header menu** switcher (`src/components/shell/warehouse-switcher.tsx`, `className` decides visibility per mount — review loop 2 made mobile a first-class mount; Esc/outside-click close the disclosure and `onPicked` lets the mobile mount close the header menu), and the Settings list. The picked warehouse is a localStorage convenience (`src/lib/warehouses.ts`) keyed **per tenant** (`wms-active-warehouse:<tenantId>`) — the backend has no active-warehouse concept until Epic 2. localStorage-derived UI state goes through `useSyncExternalStore` subscriptions (`subscribeSession`, `subscribeActiveWarehouse`) — never synchronous setState in effects.
- Sidebar IA skeleton: 12 surfaces (Overview, Inventory, Inbound, Outbound, Moves, Conflicts & Reviews, Notifications, Replenishment, Channels, Compliance, Reports / Audit, Settings) — placeholder routes except the tenancy features above; interaction primitives (⌘K palette: Esc closes, Enter commits; single modal layer) in `src/components/shell/`; cursor-pagination data-table primitive in `src/components/data-table/`.
- **Zones/bins setup + checklist (Story 1.3):** `Settings` hosts the setup checklist card (`src/components/settings/setup-checklist-card.tsx` — "N of M done" badge, progress bar, tick rows + Continue links per the overview mockup; data from `useSetupChecklist()`, `src/lib/use-setup-checklist.ts`, refetched on warehouse/zone-bin change events) and the zones/bins setup group (`src/components/settings/zone-bin-setup.tsx` — zone create, grid generator, manual bin, and the zone→bins `DataTable` with the block toggle; the warehouse being configured follows the switcher's per-tenant localStorage pick, falling back to the first warehouse). Loaders mirror `useTenantWarehouses`: `useWarehouseZones` walks the full cursor chain through the generic walker `fetchAllPages` (`src/lib/fetch-all-pages.ts`, unit-tested), `useZoneBins` serves one cursor page wired to the DataTable's Prev/Next. Zone/bin mutations broadcast `ZONES_CHANGED_EVENT` (`src/lib/zones.ts`) so the checklist and lists refetch; `rejectionReason` in the setup component branches on `duplicate-zone-code` / `duplicate-bin-code` / `grid-too-large`, never on prose.
- **Catalog setup (Story 1.4):** `Settings` gains two cards between the zones/bins group and the warehouse list. `ImportCatalogCard` (`src/components/settings/import-catalog.tsx`) is the import wizard: file picker (`.csv`/`.xlsx`, 5 MB pre-check), a **fix-run toggle** (sends `mode=fix`; default run omits the field), an honest partial-commit result banner (`N committed · M failed · K skipped` — a 201 can carry failures), the per-row error table (`{rowNumber, skuCode, code, detail}`), and a **client-generated downloadable CSV error report** (`Download error report (.csv)`, Blob + object URL). The card documents the fixed header columns and the `box:12;case:144` conversion format. `SkuTableCard` (`src/components/settings/sku-table.tsx`) is the keyset-paginated SKU `DataTable` (code, name, UoM + conversions, GST %, HSN, tracking, barcode) with an **inline edit form** below the table — GST is edited as percent and sent as basis points (`Math.round(%×100)`), an empty HSN clears to `null`; there is **no manual SKU create** (imports create SKUs). Data flows through `useSkus()` (`src/lib/use-catalog.ts` — one cursor page wired to Prev/Next, same stale-page-filtering conventions as `useZoneBins`); mutations broadcast `CATALOG_CHANGED_EVENT` (`src/lib/catalog.ts`) which `useSetupChecklist` also subscribes to (the checklist's catalog step flips on ≥1 SKU). `rejectionReason` branches on the new machine codes (`import-too-large`, `unsupported-file-type`, `file-unreadable`, `duplicate-barcode`), never on prose. Every mutating submit carries a fresh ULID `Idempotency-Key` (`src/lib/ulid.ts`).
- **Users, roles, permission gating (Story 1.5):** the stored session (`wms-session`) now carries `user {id, email, role, status}` next to the tenant — **pre-1.5 rows without `user` fail closed to signed-out** (the next sign-in rewrites the shape; sessions are 15-minute TTLs so the migration window is small). The role feeds **surface gating**: `src/lib/users.ts` holds the UI capability mirror (`ROLE_CAPABILITIES` — the backend's per-command DB read stays the authority; a stale role at worst shows a form whose submit answers `403 role-denied`, never grants one) and `roleHasCapability(role, capability)` (unknown role → `false`, fail closed). Settings cards hide what the role cannot act on — **hide surfaces, never "blocked" screens** — while read tables stay visible: the warehouse create form, the zone/bin create forms, the bin block toggle, and the SKU edit column render only for roles holding `warehouse.create` / `zone.create` / `bin.create` / `bin.block` / `sku.edit`; the catalog import card renders only for `catalog.import`; operator/accountant see lists only. `src/lib/navigation.ts` gains `visibleNavItems(role)` + an optional `capabilities` field on `NavItem` (no epic-1 nav surface declares one yet — the mechanism is ready for the operational epics) and the sidebar + mobile header menu consume it. New surfaces: **UsersCard** (`src/components/settings/users-card.tsx`, mounted in Settings) — invite form (email + role select, fresh ULID key), one-time invite link display (`/accept-invite?tenant=…&token=…`, copy button, 7-day note), users `DataTable` (email, inline role select for `users.role_change`, status pills), feedback branching on the new problem codes; **`/accept-invite`** (top-level unauthenticated route — outside both route groups by spec, `src/app/accept-invite/page.tsx` + `AcceptInviteForm` in `auth-forms.tsx`) — token + password + confirm, routes to `/login?email=…` on success; sign-in maps `invite-pending` / `invite-invalid`. The user list flows through `useUsers()` (`src/lib/use-users.ts`, external-store pattern) and mutations broadcast `USERS_CHANGED_EVENT` (`src/lib/users.ts`). **Role-change surfacing without re-login:** `refreshSessionUser()` (`src/lib/api/client.ts`) refetches `GET /tenants/{tenantId}/me` on app mount (`AppShell` effect) and rewrites the stored session's user only when id/role/status moved — best-effort, a failed refresh keeps the stored role (the backend still gates every command); a 401 there flows through the existing interceptor's `clearSession`.
- **QC holds on Inbound (Story 3.4):** the Inbound surface gains its third sibling card, `QcHoldsCard` (`src/components/inbound/inbound-cards.tsx`): open/released tabs over the warehouse's QC holds — each row names the SKU, origin bin code, reason, held-by, held-at, and status, with the **Release action rendered inside the Status column** for open rows (the `DataTable` primitive has no row-action prop). A **place-hold form** (rendered only for roles holding `qc.manage`) picks an on-hand `(sku, bin)` scope from the warehouse's stock (`useStockScopes` walks the full stock-list cursor chain, filters `quantity > 0`, options label `SKU @ binCode · N on hand`) and carries a required ≤200-char reason. Both mutations (`fetchApiPlaceQcHold`/`fetchApiReleaseQcHold`) gate on the **`qc.manage`** capability — added to the `src/lib/users.ts` mirror (owner + ops_manager; `users.test.ts` pins the matrix) — and each click sends a fresh ULID `Idempotency-Key` so a double click replays, never duplicates. Loaders follow the external-store pattern in `src/lib/use-inbound.ts`: `useQcHolds(status)` (cursor scoped to the (tenant, status) pair), `useStockScopes`, `useBinCodeMap` (per-zone bin walks → id→code map); problem codes branch through `qcReason()` (`src/lib/over-receipt.ts`: `qc-hold-open` = release the open hold first, `qc-hold-released` = refresh, `qc-hold-origin-bin-gone` = the hold stays open), never on prose. Mobile is untouched — the hold is a web Ops-Manager action.
- **Mobile was extracted to its own repo (Story 3.2):** `mobile/` moved to `wms-mobile` (`workspace/core/mobile/wms-mobile`, registered in `docs/repo-catalog.yaml` + the workspace; see `docs/repos/wms-mobile/README.md`). The `workspaces: ["mobile"]` entry, the root-tsconfig exclude, and the README run instructions are gone — the web app and the mobile app share nothing but the API contract and the design tokens.
- **Inbound + Conflicts & Reviews surfaces (Story 3.3):** the two placeholder surfaces become real, both read-only review halves of receiving. `Inbound` (`src/app/(app)/inbound/page.tsx` + `src/components/inbound/inbound-cards.tsx`) renders the active warehouse's purchase orders (PO code, vendor name, per-line ordered/received/open with the negative-open callout, open/closed status) and its goods receipt notes (GRN code, PO reference or a blind flag + reason label, line/unit counts with a "+N pending" marker for units parked on an over-receipt) — both keyset-paginated `DataTable`s behind `src/lib/use-inbound.ts` (the `useSkus` external-store pattern: tenant-scoped cursor requests, stale-page render filter). The PO list endpoint is headers-only, so each visible PO's lines come from its detail read; the GRN/over-receipt rows resolve PO codes the same way. `Conflicts & Reviews` (`src/app/(app)/conflicts/page.tsx` + `src/components/conflicts/over-receipt-queue.tsx`) is the over-receipt decision queue: pending/approved/rejected tabs, cards naming PO/SKU/excess/GRN/requester with the line's ordered/received/open context, and Approve/Reject buttons gated by `review.decide` (fresh ULID `Idempotency-Key` per decision). The nav entry now declares `capabilities: ['review.decide']` — the sidebar hides it for operator/accountant (`navigation.test.ts` pins the gate); the page itself renders read-only for them.

## Interface Contract (what this repo depends on from `wms-be`)

Keep this current whenever a cross-repo change lands — this is what lets an agent catch "this backend change breaks the frontend" *before* making the change, not after.

- Backend base URL / API version consumed: `NEXT_PUBLIC_API_BASE_URL` (default `http://localhost:3000/api/v1`), api document version 1.0.0
- Endpoints called (Story 1.1 + 1.2 + 1.3 + 1.4 + 1.5 scope): `GET /api/v1/health` (Overview page health check, live per request); `POST /api/v1/tenants` + `POST /api/v1/tenants/sign-in` (auth pages); `POST /api/v1/tenants/{tenantId}/warehouses` (Settings) + `GET /api/v1/tenants/{tenantId}/warehouses` (sidebar switcher) — the warehouse pair requires `Authorization: Bearer <token>` from sign-in and an `Idempotency-Key` on the create. Story 1.3 adds the zones/bins setup surface (all under `Settings`): `POST/GET .../warehouses/{warehouseId}/zones`, `GET/POST .../zones/{zoneId}/bins`, `POST .../zones/{zoneId}/bins/grid`, `PATCH .../warehouses/{warehouseId}/bins/{binId}` (block toggle) — every mutating call carries a fresh ULID `Idempotency-Key` per submit — and `GET /api/v1/tenants/{tenantId}/setup-checklist` (computed on read; the catalog step flips at ≥1 SKU, the users step at ≥1 invited member). Story 1.4 adds the catalog surface (all under `Settings`): `POST /api/v1/tenants/{tenantId}/catalog/imports` (**multipart/form-data** — binary `file` + optional `mode=fix`; requires `Idempotency-Key`; a 201 can carry per-row failures, so the UI renders counts + an error table, not just success), `GET .../catalog/skus?cursor&limit` (keyset page for the DataTable), `PATCH .../catalog/skus/{skuId}` (inline edit; requires `Idempotency-Key`). Story 1.5 adds the users surface: `POST /api/v1/tenants/{tenantId}/users` (invite; Owner capability — the FE hides the form for roles without `users.invite` but the backend denies anyway), `GET .../users?cursor&limit` (UsersCard table), `PATCH .../users/{userId}` (inline role change; Owner capability), `POST /api/v1/tenants/{tenantId}/accept-invite` (**unauthenticated**; `/accept-invite` page), `GET /api/v1/tenants/{tenantId}/me` (the app-mount bootstrap refetch in `refreshSessionUser()`); sign-in's response now carries `user {id, email, role, status}` alongside the tenant. See `docs/repos/wms-be/README.md` for the full request/response/error contract (story 1.5 error codes consumed by the FE: `role-denied`, `email-exists`, `last-owner`, `invite-invalid`, `invite-pending`). Story 3.2 adds the devices surface consumed by Settings' DevicesCard: `GET /api/v1/tenants/{tenantId}/devices?cursor&limit` (device table), `POST .../devices/enrollment-codes` (mint, `device.manage`, `Idempotency-Key`), `POST .../devices/{deviceId}/revoke` (revoke, `device.manage`, `Idempotency-Key`) — error codes consumed: `role-denied`, `not-found`, `idempotency-key-reuse`, `unauthenticated` (the enroll/badge-in/self-test routes are wms-mobile's contract, not wms-fe's).
- Shared types/DTOs: **generated, never hand-written** — `src/lib/api/generated/` via `@hey-api/openapi-ts` 0.99.0 (pinned). Pipeline: after any wms-be contract change run `bun run openapi:export` in wms-be, then `bun run api:generate` here, then commit the regenerated client. The generated client reads the spec from `../../backend/wms-be/openapi/openapi.json` (workspace-relative). Both CI pipelines guard this: wms-be fails if the committed spec doesn't match the code; wms-fe fails if the committed client doesn't match the spec.
  - **Mobile exception (resolved at Story 3.2):** the mobile app moved to `wms-mobile` and hand-writes its own API layer there (`wms-mobile/src/api.ts` — no codegen); a wms-be contract change that affects device endpoints breaks wms-mobile, not wms-fe.

Available seam for that story: keyset pagination on the stock list (same `Page` shape as `useSkus`), batch list `skuId`-required, detail routes tenant-level (not warehouse-scoped), unknown identity → 404 `not-found`.
